# Quickstart: Links Frontend IA - Phase 1 Repository Analysis

## Goal

Produce the phase 1 root summary and keep the project traceable for later planning.

## Inputs

- `preproyecto/2.creacion_proyecto.md`
- `preproyecto/proyecto_estructura.md`
- `package.json`
- `.specify/memory/constitution.md`
- `.specify/extensions.yml`
- `.agents/`
- `.github/`

## Phase 1 Workflow

1. Review the current repository structure and active tooling.
2. Confirm the canonical Astro config is `astro.config.ts`.
3. Collect the agent inventory from `.agents`.
4. Write `resumen_proyecto.md` in the repository root.
5. Update `preproyecto/proyecto_estructura.md` with the new phase entry.
6. Keep the output bilingual, concise, and technical.

## What the summary must include

- Repository tree in ASCII form.
- Technology and version table.
- AGENTS table with name, short description, and category.
- VERSIONS table with Madrid-local completion time.
- Mention of Speckit, `.agents`, `.github`, and `.git` as support surfaces.

## What to avoid

- Do not implement later-phase runtime features.
- Do not push to remote.
- Do not add empty contract artifacts unless a real external interface appears.

## Expected Result

A stable phase 1 documentation baseline that future phases can use without redoing the repository analysis.
